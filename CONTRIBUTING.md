# Contributing to 561 Group repositories

Thank you for contributing. Search existing issues and pull requests before opening a duplicate. Use **Bug report** for observable problems, **Feature request** for needs and outcomes, and **Maintainer task** only for accepted bounded work. Contributors can describe situations in their preferred language; evidence, screenshots, and reproduction steps are helpful but not mandatory.

For proposed changes, open a focused pull request. Explain the problem, changed behavior, checks actually performed, risks, and unresolved obligations. Follow project-specific test, development, licensing, review and release instructions; defaults do not replace local service requirements or give you authority to deploy. A GitHub issue or PR is not automatically a Group Work assignment, operating acceptance, or security clearance.

Do not put passwords, tokens, private logs, or personal data in public issues and PRs. For vulnerabilities use the affected repository's **Security → Report a vulnerability** feature when available or the [contact route](https://561.group/contact/). Commercial, purchasing and support questions belong at the contact route, not in the engineering queue.

A repository's own CONTRIBUTING, templates, owner controls and license take precedence where they exist. See the [GitHub operating model](docs/GITHUB-OPERATING-MODEL.md) for source ownership, adoption checks, and limits.
